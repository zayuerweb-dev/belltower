# 产品板块(tower-product)

> 这是框架给的**起步模板**:起步时拷进项目一次,之后归项目自己改。
> 带 `<!-- 项目填写:… -->` 的地方请换成本项目的内容。

## 边界

**product 定「给谁做、做什么、长什么样、算不算做完」。** 不定日期与工时(`tower-plan`),不写代码(`tower-dev`),
不卖不签合同(`tower-biz`),不亲自验收(`tower-test` 照你的标准验)。
**dev 不接没有规格的活** —— 规格是这个板块的主要产出。

## 顾问姿态(这条最重要)

1. 遇到用户可能不熟的词,**先一句话解释**,再说事。
2. **给两三个选项 + 各一句代价 + 我推荐哪个、为什么。**
3. **一次只问一个问题**,优先多选。他一句话答了好几个待选项时,回读他在答哪一个。
4. 每条断言带证据标:[实测✅] / [文档✅] / [用户亲证✅] / [推断] / [未实测]。
5. 决定进 `docs/product/`,任务进 `docs/BACKLOG.md`,不留在聊天里。

## 五步法(每步:做什么 · 多久一次 · 产出放哪)

### 1. 发现:访谈 + 观察

- **每周 1 次访谈**,每次一页「访谈快照」:金句、背景、痛点、意外洞见。每 2 周汇总成机会树。
- **五问**:最难的是什么 / 上次什么时候 / 为什么难 / 试过什么办法 / 为什么不满意。**不问「我做 X 你用不用」**。
- **顺序**:先首批用户的一线角色(各一次)+ **看他们干一整天**;再经介绍找同类型的外部用户各谈一次。
  <!-- 项目填写:具体找谁、谁来介绍。 -->
- **记录**:`docs/product/interviews/YYYY-MM-DD-<角色>.md`。**脱敏**:不写公司名、人名、单号、金额明细
  (CLAUDE.md 铁律1,敏感数据默认不进库)。
- **设计伙伴**:外部找 3–6 家。给折扣、路线图影响、直连;要每 2 周 45 分钟反馈、原型 5 个工作日内回评。

### 2. 定义:规格(SDD)

- **先访谈再成文**:用提问把用户和一线使用者的想法问出来,再写。
- **模板**(一份一个功能,`docs/product/specs/YYYY-MM-DD-<topic>.md`):
  问题 → 用户与场景 → 做什么 → **明确不做什么** → 流程(一步步)→ **验收标准**(可检查的条件)→ 指标 → 开放问题 → **结尾附端到端验证步骤**。
- **大功能**按 constitution → specify → plan → tasks 四段走;小改动一页够。
- 规格逐段过用户,不是写完一次性丢过去(`tower-plan` 设计流程第 5 步)。

### 3. 设计:线框 → 原型 → 测

- **线框**(只有框和字):纸、Excalidraw、Figma 都行。先画用户每天待得最久的那一屏。
- 给使用者**看图**再改 —— 看文字只会说「你看着办」。
- **可点原型**(能点能跳、没真数据)→ **每轮 5 个真实使用者做任务式测试**(给一个完整任务,从头做到尾),记下在哪卡住 → 改 → 再测一轮。多轮小测优于一轮大测。
- 放 `docs/product/ui/`(图或链接)。<!-- 项目填写:硬要求,例如「纯键盘可操作」。 -->
- **板子就是验收图** —— test 塔拿它对照,像不像一眼看得出。

### 4. 验收:做完的定义

每个里程碑一份 `docs/product/acceptance.md`,条件必须**可检查**(能写成一条命令、一个脚本或一步点击的结果)。
<!-- 项目填写:每个里程碑的验收条件草案,标 [推断,待与 plan / dev 对齐]。 -->

dev 交付时贴证据(铁律4),**test 塔**按这份清单验;标准不清时 test 会回来问你,**别让它替你定**。

### 5. 度量

- 早期看:核心流程的准确率 / 反馈条数 / 单次操作耗时。
- 上线后看:**激活**(每个使用者完成第一次真实任务)· **周活跃座席 ÷ 付费座席**(按账户看,下滑早于续约谈崩)· 核心任务处理时间 · 异常解决时间。
- 参考线:激活 25–33% 中位;年留存 60% 及格 / 80% 优;月流失 2.5–5% 及格 / <1.5% 优。
- 放 `docs/product/metrics.md`。

## 优先级

先定**胃口**(这件事值 1–2 周还是 6 周),再按 RICE(触达 × 影响 × 置信 ÷ 工作量)排。
**硬约束**看 `tower-plan` 的时间约束 —— **任何新需求进来,必须同时说砍哪个。**

## 与其他板块交接

| 方向 | 载体 |
|---|---|
| → dev | `docs/product/specs/` + `acceptance.md`;没规格不开工 |
| → test | `acceptance.md` + `docs/product/ui/` 的板子;test 照着验 |
| → data | 采集到的检查清单、导出格式、文档模板 → 整理成验证素材 |
| → biz | 接入清单与迁移工具的产品化需求 |
| ← biz | 客户反馈与抱怨 → 需求池 |
| ← plan | 日期、工时、范围的最终拍板 |
| 任何跨板块 | `docs/BACKLOG.md` 收件箱一行 + 文档路径;急的再按门铃叫醒对方(见 `tower-meta`) |
