# 运维板块(tower-ops)

> 这是框架给的**起步模板**:起步时拷进项目一次,之后归项目自己改。
> 带 `<!-- 项目填写:… -->` 的地方请换成本项目的内容。

## 边界

**管我们自己产品的线上运行,不管客户的日常业务。** 客户自己的日常操作如果另有项目承载,
在那个项目里做,不从这里伸手(CLAUDE.md 铁律2)。写代码归 `tower-dev`;ops 接手的是
**已经能跑的系统** —— dev 交付时必须带发版脚本和 runbook,**没有手册的系统 ops 不接。**

## 硬约束

- **云塔碰不到生产凭据**(凭据不进仓库、不进会话环境变量)。**真正的操作在本机或专用会话做**,
  塔只写手册、看日志摘要、定标准。
- 第三方凭据**按租户存**;有些外部接口只对「数据的合同方」开放,一套全局密钥不够。

## 一个人能维持的最低线

| 项 | 做法 |
|---|---|
| 部署 | PaaS + 托管数据库带时间点恢复;要本地部署的客户用同一镜像(如 Docker Compose) |
| 备份 | 时间点恢复 + 每日逻辑转储到另一家云;**每月真做一次恢复,每季计时演练一次**,RPO/RTO 实测值写进 runbook |
| 监控 | 错误监控 + 外部可用性探针 + 定时任务心跳;只对症状告警(延迟、流量、错误、饱和),推手机 |
| 通报 | 状态页 + 预写模板;故障中每 30 分钟更新;事后复盘 |
| 密钥 | 云原生密钥库;按角色最小权限;留访问日志;定期轮换 |
| 多租户 | 每表租户键 + 数据库层兜底(如 Postgres `FORCE ROW LEVEL SECURITY`) |
| 安全合规 | 小客户通常不要重型认证;先做「起步七件」(强制 2FA、集中日志、云审计日志、设备管理、PR + 保护分支 + CI、基础设施即代码、软件清单)+ 一页安全说明页 |

**备份没恢复过等于没有备份。** 「备份在跑」不是证据,「上月 X 号恢复到空库、耗时 N 分钟、行数对上」才是(铁律4)。
