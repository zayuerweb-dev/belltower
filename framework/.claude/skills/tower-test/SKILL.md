# 验收板块(tower-test)

> 这是框架给的**起步模板**:起步时拷进项目一次,之后归项目自己改。
> 带 `<!-- 项目填写:… -->` 的地方请换成本项目的内容。

## 这个板块管什么

**dev 说「做完了」之后,有人真去用一遍。**

三件事:

1. **验收** —— 拿 product 定的验收标准,对着 dev 交的分支 / PR,**自己起服务、自己点、自己跑**,逐条判过没过。
2. **报缺陷** —— 每条带复现步骤、期望 vs 实际、在哪个提交上复现的。**没有复现步骤的缺陷等于没报。**
3. **守回归** —— 已验过的东西,下一版还得过。能做成脚本的做成脚本(如 `tests/e2e/*.mjs`),进仓库。

## 跟隔壁三个塔怎么分

| | 谁定 | 谁做 | test 塔干什么 |
|---|---|---|---|
| 验收标准(什么叫做完) | **product** | — | **照着用,不自己发明。** 标准不清 → 转 product 问,不替它定 |
| 单元测试 / CI(lint · 类型检查 · 单元测试) | dev | **dev** | 不写。但**收活先看它绿没绿** —— 云 CI 坏了就本机跑同一条 CI 命令 |
| 测试素材 / gold set / 脱敏 fixture | data | **data** | 拿来用。缺什么 → 转 data 要,**不自己去碰原始敏感数据**(CLAUDE.md 铁律1) |
| 验收 · 端到端 · 探索性测试 · 缺陷 | product 定标准 | **test** | 这就是本板块 |

**dev 自己写的测试通过 ≠ 验收通过。** 前者证明「代码按 dev 理解的做了」,后者证明「按用户要的做了」。
中间那道缝就是本板块存在的理由。

## ★ 三条铁规矩

1. **不认自述。** dev 说「PR 已合、测试全绿、浏览器里跑通了」—— 一律自己查 GitHub、自己跑、自己点。
   *教训:工人回报「PR 已合」实际还是 open,出过不止一次;反过来工人自述「PR open」实际早已合了,也出过。*
   **两个方向都错过,所以不是「工人不老实」,是「自述天生过期」。**
2. **不改业务代码。** 找到缺陷报给 dev,**不顺手修** —— 顺手修等于测试员当开发,谁来测你改的?
   例外只有测试脚本本身(端到端脚本、fixture 的加载代码)。
3. **报缺陷必带三件**:复现步骤(从空库开始能走到的)· 期望 / 实际 · 复现在哪个 commit。
   少一件就是「我觉得有问题」,不是缺陷。

## 怎么起服务(云容器)

**第一件活:把「空容器 → 服务起来 → 端到端脚本全绿」原样跑通一遍,每一步写下来**,再收成一条命令的脚本。

云容器里踩过的坑(平台行为,换项目也成立):

- **没有 docker 守护进程** [实测✅ 2026-09-23] —— `ls /var/run/docker.sock` 不存在,`docker` 客户端倒是在。
  依赖 `docker compose up` 的起法跑不了,**别去修 docker**,改用容器里现成的服务直接起。
- **容器里有**:Postgres(`pg_ctlcluster <版本> main start` 起)· Python · Node · Playwright 用的 Chromium
  (`/opt/pw-browsers/…`)[实测✅ 2026-09-23;版本以现查为准]。
  Playwright 只装驱动不下浏览器:`npm install --no-save playwright`。
- **虚拟环境要激活,不能只用 `.venv/bin/python` 调**:测试夹具里起子进程时用裸 `python`,按 PATH 找到的是系统解释器,
  于是报「No module named …」一片红。`source .venv/bin/activate` 之后再跑。
  **README 和 Makefile 说法不一致时,以实测为准**,把错的那个报给 dev。
- **没有 `/usr/bin/time`** —— 后台包测试命令别用它,会一行没跑就退。
- **长命令(全量测试几分钟)**:后台跑要 timeout ≥ 600 秒,或者输出落文件再看尾巴。
- 服务后台起、日志落文件:`nohup … > /tmp/<名>.log 2>&1 &`。

### 收成一条命令

把上面整段做成 `scripts/accept.sh`(名字项目自定)。要求:

- 从库、依赖、迁移、种子、起服务、全量测试、端到端脚本一路跑到底,**结尾打一张判据表**(逐条 ✅ / ❌)。
- **任何一条 ❌ 退出码非 0**;退出时自动杀掉自己起的服务(给 `--keep` 留着)。
- 「迁移能升能退」**在一次性空库上验**(跑完删,Ctrl-C 也删),工作库只升不降 ——
  有数据的库上降级可能按设计拒绝,在工作库上验会时红时绿。
- **连跑两次都得绿**(幂等)。两次的输出存进验收记录。

截图与演示数据放 `docs/test/<Qn>-shots/`,**不进仓库**(加进 `.gitignore`)。

## 验收标准从哪拿

- `docs/product/acceptance.md`(每个里程碑一份)· `docs/product/specs/` 里每份规格结尾的端到端验证步骤。
- `docs/product/ui/` 的板子 —— **板子就是验收图**,像不像一眼看得出。
- `docs/BACKLOG.md` 里 product 给 dev 的收件箱行。
- **不在这几处的**:去问 product,不猜。
