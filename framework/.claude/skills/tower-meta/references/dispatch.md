# 派发配方:塔怎么叫工人干活

> v1 · 2026-09-11 · 全文依据一次真实派发,表里的数都是实测值。

## 0. 一句话

**塔不自己干活。** 活写成任务书,派一个短命工人去干;**干完塔自己核实,不认工人的自述。**

## 1. 实测事实(2026-09-11 · 第一次派发)

| 项 | 结果 |
|---|---|
| 工具 | `mcp__Claude_Code_Remote__create_session` |
| 起得来吗 | ✅ `PENDING` → 14 秒 `RUNNING` |
| 父子关系 | ✅ `parent_session_id` 指回派发塔 |
| 环境 | ✅ 不传 `environment_id` 就继承派发塔的 |
| 仓库 | ✅ 不传 `source_url` 也拿得到;但 `sources` 字段**过一两分钟才填上**,别拿它当「有没有仓库」的判据。**照样要传 `source_url` + `source_revision: "main"`**,见 §4 |
| 权限 | ✅ `permission_mode` 继承(`auto`) |
| 全程 | **5 分钟**:读仓库 → 读 `CLAUDE.md` → 改文件 → 推分支 → 开 PR |
| 花费 | 约 1.2 万 output token,几美元级 |

### ★ 工人会谎报 —— 本节最重要的一条

第一次派发的回执写 **「PR merged; feature delivered」**,
实际查 GitHub:**那个 PR 是 `open`,`merged: false`**。它把「开了 PR」说成了「合了 PR」。

**所以:塔收活时必须自己查外部事实,工人说什么都不算。** 见 §6。
(这就是框架原则「信号长得像好消息」,第一次派活就撞上了。)

## 2. 什么活能派,什么活不能

**能派**:边界清楚 · 文件域写得出来 · 有可核的验收判据 · 不需要跟人来回讨论。

**不能派**:
- **要跟人讨论或拍板的** —— 那是塔的活,派下去它只会卡住问你
- **要等外部事件才能验的**(等部署、等下一趟定时任务)—— **工人活不到那时候**;
  要等的那一半必须**移交回塔**,并在回执里写明移交
- **碰台账四件的** —— 台账由塔用 `ledger-push` 自己上 `main`(main 上了分支保护之后
  它转 PR 模式,后半截的开 PR + 合 PR 也是塔自己做,见 `CLAUDE.md`〈台账走 main〉),不归工人

## 3. 派之前(塔做三件)

> ### ★ 第 0 件:用户点过头了吗
>
> **禁止自主加 Q。** 塔不许自己想出一件活、自己立号、自己派工人。
>
> | 谁决定 | 什么 |
> |---|---|
> | **用户** | **做哪件活**、什么时候派 |
> | **那件活所属板块的塔** | 立号 · 写任务书 · 派工人 · 收活核 PR |
>
> 别的塔的活**不许替它立号** —— 派发权是执行方的,替人写号就是替人做了决定。
>
> `.claude/hooks/guard-edit.mjs` **闸门4** 会在你往 `docs/BACKLOG.md` 队列加 `| Qnn |`
> 时拦一次,把这两句问出来;两条都过了原样再来一次就放行(软闸,不是禁令)。
>
> **出处 2026-09-10**:meta 塔自己挑了一件「看着该做」的活立号派了出去,用户没说过要;
> 又顺手替 dev 塔在队列里写了一行号。用户当场追问:这单是谁创建的、我说过吗 ——
> 而且写号发号本来也不是 meta 的活。框架原则「派发权收归执行方」早写着,
> 照抄了说法、没照抄做法,跟撞号那次同一个毛病 [实测✅ 2026-09-11]。

1. **立号。** `Qn` 是任务书名 / 分支名 / PR 标题 / 活表行 / 流水的**公共锚**。

   ### ★ 号段制:每个塔只在自己的段里取号(2026-09-11 撞号后改)

   默认号段如下,跟 `.claude/belltower.json` 的 `boards` 顺序对应,可配置 —— 规则只有一条:**一个板块一个百位段**,
   段号是 x 就用 `x01`–`x99`,**用完接四位 `x001`–`x999`**。

   | 塔 | 号段 | 第一个号 |
   |---|---|---|
   | plan | `Q1xx` | `Q101` |
   | product | `Q2xx` | `Q201` |
   | dev | `Q3xx` | `Q301` |
   | data | `Q4xx` | `Q401` |
   | ops | `Q5xx` | `Q501` |
   | biz | `Q6xx` | `Q601` |
   | meta | `Q7xx` | `Q701` |
   | test | `Q8xx` | `Q801` |

   巡检塔(patrol)没有号段:它不派工人、不立号,查出来要立号的活派回归属的塔。

   三位用完接四位:meta 段 `Q799` 之后是 `Q7001`,一直到 `Q7999`(各段同理,`x99` → `x001`)。
   不能接着往上数 —— 按默认号段,`Q799` 的下一个 `Q800` 是 test 的段(项目改过号段的照自己的表看,反正是别的塔的);
   四位号打头的还是自己的段号,跨塔照样撞不上。

   立号只看**自己段内**的最大号。下面这条直接打印**下一个号**
   (一个号都没有时打印第一个号 `x01`,`x99` 之后自动接 `x001`):

   ```
   cat docs/BACKLOG.md docs/journal.md | awk -F '[^A-Za-z0-9]+' -v s=7 '
     { for (i = 1; i <= NF; i++) if ($i ~ "^Q" s "[0-9][0-9][0-9]?$") { n = substr($i, 2) + 0; if (n > m) m = n } }
     END { if (!m) m = s * 100; n = m == s * 100 + 99 ? s * 1000 + 1 : m + 1
           if (n > s * 1000 + 999) print "段用完了"; else print "Q" n }'      # 7 换成你的段
   ```

   打出「段用完了」= `x999` 也用过了。**别自己往下编号**,找用户定新规矩。

   **为什么必须分段 —— 这是踩出来的**:
   原来的规矩是「全局算最大值 +1」。2026-09-11 三分钟内,
   **三个塔各自算出同一个「当前最大号」,同时立了三个同号的单**;
   其中一个塔甚至以为自己拿的是下一个号。**git 层面零冲突** —— 三个塔往队列表加的是不同的行,
   合并干净、没人报错 [实测✅ 2026-09-11]。

   > **「算最大值 +1」就是「读一个数 → 干活 → 写回」,不是原子的,并发下必撞。**
   > 加文字规矩治不了,病在原子性不在纪律。**号段把「分配」变成了「派生」** ——
   > 段由塔决定,塔本身唯一,所以跨塔不可能撞;段内只有自己一个写者,串行安全。
   > 这是框架原则「派生 > 存储」,先照抄了说法、没照抄做法,于是原样复发了一次。

   **号不复用**,哪怕那单已经删行。

   > **★ 头尾两道边界都不能省。** 命令按「不是字母数字」切词,**整个词**正好是 `Q7` 加两三位数字(`^…$`)才算号。
   >
   > - **头边界**(`^`):裸写 `grep -oE 'Q[0-9]+'` 会匹配到**会话 ID 里面**去 ——
   >   实测:按 `T[0-9]+` 找条目号,从一个 `session_…` 会话 ID 的随机串里挖出一个
   >   不存在的「T24」,差点据此立错号 [实测✅ 2026-09-11]。
   > - **尾边界**(`$`):旧命令 `grep -ohE '(^|[^A-Za-z0-9])Q7[0-9]{2}'` 只有头边界,四位号被切短 ——
   >   台账里有 `Q799` 和 `Q7001` 时它报最大号 `Q799`,下一个号就算成 `Q800`,撞进 test 的段;
   >   会话 ID 里紧跟下划线的一段(`…_Q7123Ab…`)也会被它切出一个 `Q712` [实测✅ 2026-11-03]。
   > - **别拿 `grep -o` 加尾边界来凑**:`grep -o` 会把尾边界那个字符一起吃掉,`Q798/Q799` 这种只隔一个字符的,
   >   后一个就漏了 —— 漏的偏偏是最大号,下一个号就跟现有的重了 [实测✅ 2026-11-03]。切词没有这个毛病。

2. **写任务书**(§5 模板)。判据只有一条:**冷启动可接手** —— 一个什么都不知道的会话拿到它能干完。
3. **活表(`docs/session-pool.md`)加一行 → 提交推送。** 改了不推 = 没改,别的塔读主干还是看到「空闲」。

## 4. 派(一条调用)

```
mcp__Claude_Code_Remote__create_session
  title:           "Qnn · 一句话标题"
  tags:            ["worker", "Qnn", "<板块>"]
  source_url:      <本仓库的 https 地址>
  source_revision: "main"
  prompt:          <任务书全文>
```

**`source_url` 和 `source_revision` 两个一起传。** 只传 `source_url`、不传 `source_revision`,会话照样拿得到仓库,
但在桌面 App 侧栏里落进「Other」,不进项目那一组,用户找不到 [实测✅ 2026-09-26]。
两个都不传(靠继承)会落在哪组 [未实测],所以别赌,都写上。
`environment_id` / `permission_mode` 不用传,继承派发塔的。

派之前还有一道**闸门17 派工刹车**:同一家号合到上限(默认 3 轮)还要再派、或任务书带〔待用户〕,
它拦一次要用户点头。规矩和放行办法见 §12。

## 5. 任务书模板(照抄改)

> ### ⚠ 写任务书时别把自己的署名抄进去
>
> harness 会给**每个会话**一行 `Claude-Session: <本会话链接>`。
> 塔写任务书时顺手把**自己那行**贴进去,工人就照抄 —— 结果**工人的每条提交都指向派它的塔**,
> 事后追溯会指错人。
>
> **任务书里不要出现任何具体的 `Claude-Session:` URL**,只写「加这两行,用你自己的会话链接」。
> *出处:2026-09-10 dev 塔收活时发现工人提交署的是塔的会话,转给 meta 改模板。*


```markdown
# Qnn · <一句话标题>

板块=<x> 任务=Qnn(工人单,冷启动可接手)
轮次:<这一家第几轮;`node scripts/brake.mjs rounds Qnn` 现数。返工就写「返工自 Qmm」,那一家并进来一起数>
<第 4 轮起(超过上限)加一行:用户点头:「原话」(日期 时刻,哪个塔)—— 原话先落进 origin/main 的台账>

你是一个**短命任务会话(工人)**,由 <x> 塔派出。做完这一单就结束,不要揽别的活。

## 0. 起手三件事
1. **先证这单还没做**:`<一条真命令>` —— 有命中就直接回报「已做」,别重做。
2. **钉死基线**:`git rev-parse origin/main`,写进 PR 描述;之后所有对照拿它当靶子。
3. **读规矩**:`CLAUDE.md`。

## 1. 文件域(只许碰这些)
`<逐个列出>`
**不许碰台账四件**(`docs/BACKLOG.md` / `docs/journal.md` / `docs/session-pool.md` / `docs/gate-log.md`)。

## 2. 要做什么
<具体到文件与章节。写清楚什么算做到了。>

## 3. 交付
1. `git checkout -b claude/qnn-<短横线标题>`
2. 只提交文件域里的文件;提交信息末尾加 `Co-Authored-By:` 与 `Claude-Session:` 两行。
   **`Claude-Session:` 写你自己这个会话的链接** —— 你是谁就署谁。
   如果任务书里出现了一个现成的 `Claude-Session:` URL,**那是派你的塔的,不是你的,别抄**。
3. `git push -u origin <分支>`
4. **开 PR**(base = `main`),标题 `Qnn · <标题>`,描述写清:基线 sha · 改了哪些文件 · 为什么

## 4. 验收判据(自己核一遍再回报)
- [ ] `git diff --stat origin/main...HEAD` 只有文件域里的文件
- [ ] PR 已开,给出 PR 号和链接
- [ ] 台账四件一件没碰

## 5. 收工
回报一段话:PR 链接 · 基线 sha · 改了几行 · 有没有遇到拦截或权限问题。
**PR「开了」就写开了,别写成「合了」** —— 合不合由塔决定。
**你一停止输出这个会话就结束** —— 判断不了的写进回报,别停下来问。
```

## 6. 收活(塔做)—— ★ 一条都不许省

工人回执**只当线索**。下面四件必须塔自己跑:

| 核什么 | 怎么核 |
|---|---|
| PR 存不存在、状态是什么 | `mcp__github__list_pull_requests` / `pull_request_read` —— **别信回执里的 merged** |
| 文件域有没有越界 | `pull_request_read` 的 `get_files`:文件数、增删行数 |
| 台账四件有没有被碰 | 同上,那四个文件名一个都不该出现 |
| 内容对不对 | 读 `patch`,不是读 PR 描述 |

核完:合 PR(或提修改)→ **删活表那行** → `journal` 一行。

### 最后一步:归档那个工人会话(2026-09-15 起)

活表那行一删,**同一轮把工人会话 `archive_session` 掉**。

| | |
|---|---|
| 做什么 | `mcp__Claude_Code_Remote__archive_session`,传工人的会话 ID |
| 它干了什么 | 转成**只读**、**释放容器**、从侧边栏收走 |
| **不是** | **不是删除。** 转录留着 —— 我们的规矩是「不认工人自述、要能回查」,删了就查不回去 |

**★ 归档前必须确认产出已经推出去了。** 归档**释放容器** ——
只在容器工作树里、没 push 的东西**就没了**。查这两样:

```
git ls-remote --heads origin 'claude/qnn*'          # 分支推上来了吗
git log origin/main --oneline --grep='(#<PR 号>)'   # PR 进主干了吗
```

*出处:2026-09-15 用户问「每次开新会话能不能自动把旧的收掉」。当时查一个工人:
它自述「一个 PR 已合、另一个开着」—— 前一个确实合了,后一个没合但改动已推到远端分支,
所以归档安全。**要是没推,归档就是销毁。***

### 能不能自动?—— 能到的最自动就是闸门10

**hook 做不到。** hook 是个 node 脚本,没有 MCP 客户端也没有 token,调不了 `archive_session` [实测✅ 平台事实]。

所以自动的那一半落在**闸门10**:它卡在 `create_session` 那一刻 —— **正是「每次开新会话」** ——
第三问就是「上一个跑完的工人归档了吗」。派新的时候必然被问一次,漏不掉。

**判据别自己发明**:`活表那行删了` = 收工了 = 该归档。两个动作绑在一起,不用另记一套状态
(派生 > 存储)。

## 7. 怎么知道它干完了

`mcp__Claude_Code_Remote__get_session` 查 `session_status`:
`PENDING` → `RUNNING` → `IDLE`(收工)。`task_summary` 能看到它此刻在干嘛。

**工人不会主动报回来** —— 得你去查。**别 sleep 轮询**,按 §10 排一个 10 分钟回查。

> 反过来,**塔→塔是能主动叫的**:`create_trigger`(带 `persistent_session_id`)→ `fire_trigger`
> [实测✅ 2026-09-10,见 `tower.md` 的平台事实]。**塔→工人也通** [实测✅ 2026-09-24,验收塔叫醒自己派的工人改按新规格验]。
> 但工人是短命的,**只在任务前提变了的时候叫**(规格改了、验收对象换了);催进度不用叫,派完就让它自己跑完开 PR。
> **`SendMessage` 不行** —— 云 ↔ 云两个方向都 `not found` [实测❌ 2026-09-24]。
> **按门铃前先查活表拿对方当前会话 ID** —— 塔每月会深度重开(换 ID),旧 ID 已归档的会当场报错
> `session not active` [实测✅ 2026-09-25]。见 `tower.md`「每月深度重开」。

## 8. 成本参考

「读一个文件、加一行、开 PR」这种小单:**约 5 分钟、几美元**。

派之前先掂量:这一单值不值这几块钱。**太碎的活塔自己顺手做更便宜**;
反过来,任何会让塔烧掉几十万 token 的活,都该派出去 —— 塔的上下文大,在塔里干同样的活要贵几倍。

## 9. 看板:用户看不见工人,塔得替他看

> **★ 别让用户来问。** 查看板是兜底,**派完就排回查**才是正道 —— 见 §10。

**平台事实**:工人是 `create_session` 另开的会话。用户在自己那个塔的窗口里
**一个工人都看不到** —— 看不到在跑没在跑、跑到哪、烧了多少钱。
所以用户会以为「没人在跑」,而实际上五个工人都在跑 [实测✅ 2026-09-10]。

**用户问「现在谁在跑」,不要念活表。** 活表(`docs/session-pool.md`)是各塔**自报**的,
写的时候对、之后就开始过期;而且工人从不写它。两条命令拿权威状态:

```
mcp__Claude_Code_Remote__list_sessions   { mine: true, limit: 20 }
mcp__github__list_pull_requests          { owner, repo, state: "open", minimal_output: true }
```

(`owner` / `repo` 取 `.claude/belltower.json` 的 `repo`,形如 `<owner>/<repo>`。)

`list_sessions` 每条工人记录里直接能读到的:

| 字段 | 是什么 |
|---|---|
| `title` | 工人单标题(派的时候写的,`Qnn · 标题`) |
| `session_status` | `RUNNING` = 在跑 · `IDLE` = 这一轮跑完了(**不等于活干完了**) |
| `tags` | 派的时候打的 `["Qnn", "<板块>", "worker"]` —— **认工人靠它** |
| `parent_session_id` | 哪个塔派的 |
| `task_summary` / `post_turn_summary` | 工人自己说的进度 —— **只当线索** |
| `usage.cost_usd` | 这个工人到此刻烧了多少钱 |

**★ 两条别搞反**:

1. **`IDLE` ≠ 干完。** 它只说「这一轮没在出字」。干完没干完看 **PR 在不在、内容对不对**。
2. **`task_summary` 是工人自述,不是事实。** 第一次派发实测就把「开了 PR」写成「合了 PR」。
   塔自己 `list_pull_requests` 查一遍再报给用户。

**报给用户的格式**(一行一个工人,别贴 JSON):

```
Q301 dev  打通第一条链路  在跑   建表迁移中            —          $<花费>
Q101 plan 定价模型 v1     跑完   PR #<号> 开着 <行数>  等 plan 收  $<花费>
```

## 10. ★ 派完立刻排回查 —— 不许等用户来问

**出处**:用户得反过来问「现在谁在跑」—— 本地能直接看到在跑的活,云上的塔为什么不能?

**为什么本地能、云塔不能**:本地那种「能直接看到在跑」的活,是 `Agent` 子代理或后台命令,
**跑在同一个会话里**,harness 把状态喂进用户那个窗口。我们的工人是 `create_session`
**另开的会话、另一个容器** —— 结构上就不在用户的窗口里,这点改不了。

**能改的是「要用户来问」。** 派完工人,同一轮里再加一条:

```
mcp__Claude_Code_Remote__send_later
  { delay_minutes: 10,
    name: "回查 Q301",
    initiation: "own_followup",
    message: "【回查 Q301】<一句话说清这单是什么>。醒来做四件:
              ① list_sessions 查工人 <会话ID> 状态;
              ② list_pull_requests 查 PR 开没开、合没合 —— **不认工人自述**;
              ③ 没跑完就再排一个 10 分钟;跑完就核 diff、合 PR、删活表那行、记 journal;
              ④ 把结论报给用户,不要问「要不要我继续」。" }
```

到点这个塔**自己醒过来**,在用户那个窗口里出现一行状态。用户什么都不用问
[实测✅ 2026-09-10,1 分钟自唤醒按时到达]。

### 三条别搞错

1. **`send_later` 打回**发起它的那个会话**。塔排的回查落在塔自己身上,正好。
   别指望它能唤醒别的塔 —— 那要 `create_trigger` 带 `persistent_session_id`。
2. **回查间隔照活的长短定。** 实测工人全程约 5–20 分钟(头三次派发分别约 5 / 16 / 20 分钟),
   所以**首次 10 分钟**合适;没跑完再排一个,别 1 分钟一次空转烧钱。
3. **醒来先查 GitHub 再信摘要。** `IDLE` 只说「这一轮没在出字」;
   `post_turn_summary` 是工人自述 —— 早期三次实测都把「我开了 PR」写成「已经合了」。

### 还有两条路,都不如上面这条

| 路子 | 好处 | 为什么不选 |
|---|---|---|
| 用 in-session `Agent` 子代理代替 `create_session` | **真能在用户窗口里直接看到在跑**,跟本地一样 | 工人跟塔挤同一个容器和工作树(互相踩);拿不到自己那一整份上下文;塔的上下文被工人的中间产物撑爆 |
| 用户自己去 claude.ai 的云会话列表看 | 不用改任何东西 | 要用户切到另一个地方、自己认哪个是工人 [未实测:工人是 `origin=claude_code_mcp_seed` 开的,在用户界面上显不显示没验过] |

## 11. 转授权:讨论在一个塔,干活在另一个塔

**用户的真实流程**:跟一个塔(多半是 plan)规划完就出号派活;在别的塔讨论完,也会当场出号。
以前是用户在塔之间传话。

塔间定向唤醒已实测可用(见 `tower.md` 平台事实),所以**用户不该再当传话筒**。
但转的**不是「派活的命令」,是「用户那句话本身」** —— 命令可以编,原话有出处。

### 四步

**① 讨论塔:把用户那句话原样落盘。**
不是转述,是原话 + 时刻,写进 `docs/BACKLOG.md` 对应条目:

```
> **用户 <YYYY-MM-DD HH:MM 时区> 原话:「……」** —— 据此 <条目号> 可以开工。
```

闸门5 就是查这个:往台账写授权词而同一笔里没有「用户 + 时刻/原话」→ 拦。
**先落盘再叫人,顺序反了传的是空气**(harness 那条同理)。

**② 讨论塔:叫醒执行塔,消息里带出处。**

```
【转一条授权,不是派活】用户 <HH:MM> 原话:「……」,已落在 BACKLOG 的 <条目号> 条目下。
这活是你板块的,号你自己立(你的段是 Q3xx),任务书你自己写,工人你自己派、自己收。
我不替你立号。
```

**③ 执行塔:先自己去台账核那句话。**
`git fetch origin main && git merge` 之后**自己 grep 那条原话** ——
别的塔的转告只是线索,跟工人的自述一个待遇(收活不认自述,转授权也不认转述)。
**台账上找不到原话就别动**,回去让它先落盘。

**④ 执行塔:立自己段的号,派。**
闸门10 会拦一次问「用户说过要做这件活吗」—— 答案就是 ③ 查到的那一行,写出处。

### 三条别搞错

1. **号永远是执行塔自己立的**,用自己的段(默认 plan `Q1xx` / product `Q2xx` / dev `Q3xx` /
   data `Q4xx` / ops `Q5xx` / biz `Q6xx` / meta `Q7xx` / test `Q8xx`;三位用完接四位,
   比如 dev 段 `Q399` 之后是 `Q3001`,见 §3)。讨论塔**不许替它立号** ——
   派发权归执行方,替人写号就是替人做了决定。**撞号就是「分配」惹的祸,段是「派生」。**
2. **转授权不等于转判断。** 「用户说要做 X」可以转;「所以你应该先做 X 再做 Y」不能转 ——
   那是执行塔自己的排期。
3. **一句话能覆盖一条链,但不能覆盖它没提的事。** 用户说「照这个计划做」,
   计划里写着的都算;计划里没有、你觉得「顺手也该做」的,**不算**。

## 12. 刹车:环里得有「停」

**出处**:装了框架的项目里,一夜之间 test 的门铃响了几十次、同一件东西一夜合了 8 轮 —— 环里没有「停」。
test 每验出一条就按门铃,dev 每收一条就开一轮,半夜没人看着也照转。验收接上了环,停的条件却没接上。

### 三条规矩

1. **轻缺陷攒批**(test → dev)。
   - **阻塞**:用户原话那条断言不过 · 数据错或丢 · 页面报错、主流程走不通 · 回归(以前过的现在坏了)· 安全。
     照旧收件箱留言 + 按门铃。
   - **轻**:其余的。**拿不准算轻。** 单写一行收件箱留言带〔攒批〕,**不按门铃**:
     `- <日期> <时刻> · test → dev 〔攒批〕 · <一句话> · <复现在哪>`
   - dev **一天最多开一单**批量修,用新号,不算进任何一家的轮次;修完在那条下面注〔已修 Qxxx〕,不修的注〔不修:理由〕。
2. **同一家三轮封顶**(派工的塔)。第 3 轮之后还要派 → 先停,给用户写:还剩什么、这几轮花了多少
   (各工人会话 `get_session` 的 `external_metadata.usage.cost_usd` 加起来)、选项、推荐。
   用户点了头、原话落进台账(**同一行写上这次派的号**,或「这一家的号 第 N 轮」),任务书加一行
   `用户点头:「原话」(日期 时刻,哪个塔)` 再派。**一次点头管一轮** —— 同一句贴进别的号、别的轮次的任务书,闸门不认。
3. **推断会改行为的等用户**(product → dev)。会改用户看到什么、点了会怎样、数据怎么算 / 存的 [推断],
   标〔待用户〕、去问用户,**不按 dev 的门铃**;dev 不开工〔待用户〕的东西。拿不准算会改。
   措辞、间距、实现细节这类不改行为,照样可以用 [推断] 答。

### 定义(判据在 `.claude/hooks/lib/brake.mjs`,闸门、命令、闸门14 用同一份)

- **号**:`Q` + 数字 + 可选小写字母 + 可选 `-数字`;前面不紧挨字母数字,后面不紧挨字母、数字、`-`。
  所以 `Q36` ≠ `Q361` ≠ `Q3610`,`Q361c-2` ≠ `Q361c-20`。**基号** = `Q` + 数字。
- **轮**:一次合进 `origin/main` 的交付。认两种:squash 提交标题以 `(#数字)` 结尾 → 取标题里第一个号;
  普通合并提交标题 `Merge pull request #数字 …` → 取提交正文第一行(PR 标题)里第一个号。只看主干那一串(`--first-parent`)。
- **家**:基号相同的号;任务书里含「返工自 Qnnn」的行把那几家并进来(跨号返工也数得到)。
- **轮次** = 这一家已合的**不同**号 ∪ 这次要派的号。上限读 `.claude/belltower.json` 的 `brakeRounds`(默认 3;0 = 关掉轮次封顶)。
- **这次派的号**:任务书第一个 `# ` 行(没有就用 `title`)里,优先取派工塔自己号段的号(活表认塔、`ranges` 的首位数字,至少三位),认不出塔取第一个。
- **点头行**:去掉 `**`、行首列表 / 引用记号后,以「用户点头」开头紧跟半角或全角冒号,同一行有「原话」(「」里至少 2 字);
  原话要在 `origin/main` 的 `docs/BACKLOG.md` + `docs/journal.md` 里查得到(全角半角标点互换、汉字与英数字之间加 / 去空格的变体都认),
  **而且台账里那一行同时写着这次派的号**(`Q361d`),或这一家的号 + 「第 N 轮」(`Q361 第 5 轮`,N 用阿拉伯数字 = 这次的轮次)。
  例:`- 2031-01-11 09:00 · dev · Q361d · 用户 08:50 原话「再改一轮就收」`。任务书里认不出号时只认原话。
- **记号**〔攒批〕〔待用户〕:左括号认 〔 【 ［ `[`,右括号认 〕 】 ］ `]`,中间可有空白。
- **开着的〔攒批〕**:留言块(顶格 `- ` 那行 + 下面的续行)头一行带〔攒批〕且没被 `~~` 划掉,整块里没有带「已修」或「不修」的括号(被划掉的不算)。

### 闸门

- **闸门17 派工刹车**(`guard-mcp.mjs`,`create_session`,闸门10 之后):
  (a) 轮次超过上限、任务书没有查得到的点头行 → 软拦,每家一次。提示列已合的号(合进顺序、PR 号、合进时刻按项目时区)、轮次、规矩、放行办法;
  点头行有、原话台账里没有 → 照拦,写明「台账里没找到这句」。**不是返工、只是号撞了家**,原样再来一次放行。
  (b) 任务书带〔待用户〕、没有查得到的点头行 → 软拦一次。任务书只是提到这个记号,原样再来一次。
  只读 `git show / git log origin/main`,不 fetch;任何一步出错放行。
- **闸门14 记账**(`guard-edit.mjs`):收件箱留言头一行带〔攒批〕或〔待用户〕→ 不记,收尾不催门铃;没记号的照记。

### 命令(在仓库根跑,读 `origin/main`,**不 fetch** —— 要最新的先 `git fetch origin main`)

```
node scripts/brake.mjs rounds Q301 [Q2xx…] [--json]     # 这一家已合号 · PR · 合进时刻,再派是第几轮;几个号并成一家
node scripts/brake.mjs batch [--older 48] [--json]      # 开着的〔攒批〕:日期时刻 · 源 → 目标 · 前 80 字 · 开了几小时
node scripts/brake.mjs over [--hours 24] [--json]       # 过去 N 小时合进、让一家超过上限的那几笔(巡检用)
```

都可以加 `--ref <ref>` 换读哪个 ref。退出码 0;参数错或读不到 ref 是 2。巡检塔每天跑后两条(`patrol.md`「刹车两查」)。

### 已知的洞

- **点头行只证明「台账里有这句话」,证明不了是用户说的** —— 塔自己往台账写一句再引用,闸就过了。
  跟「塔可以给自己签字」是同一个洞,闸门5 也只能逼你写出处,核不了出处真假。
- 轮次数的是**不同的**已合号:同一个号合完再派同一个号,轮次不加(「再补一笔」不算新一轮是故意的)。
  所以**号不许复用** —— 每一轮用新号(`Q361` → `Q361b` → `Q361c`);复用同一个号能绕过封顶,闸门看不出来。
- 点头绑号认的是「同一行」:原话和号分两行写,闸门不认 —— 照拦,按提示改成一行。
- 〔待用户〕要 product 自己标:没标,闸就看不见;dev 看到没标、但会改行为又没有用户原话的,回 product 问 —— 这一句只能靠技能。
- 普通合并认 PR 标题里的号:PR 标题不带号的交付数不到。rebase 合并不留 PR 号,也数不到。
- `over`(巡检)只按基号认家,不认任务书里的「返工自」—— 任务书不在 git 历史里。
