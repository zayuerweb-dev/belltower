# 中枢板块(tower-meta)

> 这个 skill 是框架中枢。协议细节在两份参考文档里:
> `references/tower.md`(塔协议:身份、门铃、生命周期)· `references/dispatch.md`(派工人配方、回查、收活)。

## 会话生命周期

开局声明板块 + 任务(SessionStart hook 会提示)→ 换阶段说一句 → 收尾 journal 一行。

**开局同步要 merge,不能只 fetch**:`git fetch origin main && git merge --no-edit origin/main`。
`CLAUDE.md` / `.claude/skills/` / `scripts/` 都从**工作树**加载,不 merge 就读不到新的。

**落盘先于压缩**:长任务上下文过半,先把「做到哪 / 下一步」写回 `docs/` 再继续。
compaction 丢细节无所谓,细节已经在盘上。

塔是长命会话,它的身份怎么现查、自动压缩阈值、定期深度重开、每日清理,见 `references/tower.md`。

## 上下文经济六条

图不进主会话 · 大文件禁全读(Grep 切片)· 长输出必截 · 读过不重读 ·
一会话一任务 · 落盘先于压缩。

正解是**让信息可以被便宜地找到**(文档 + 目录 + Grep),不是「忍着不看」。

## subagent 判据

**过程不需要留在上下文里的活,全部外包。**

- **派**:搜索定位 / 读大文件回答案 / 看图 / 长命令收摘要 / 多处独立排查(并行同发)。
- **不派**:主线活 —— 连续判断、来回改代码、与用户对话。
- **纪律**:派了别自己再干一遍;**结果没回来别编**(完成通知永远不是自己写的)。
- **只读复查必须限权**:派 `Explore` 型代理,或通用型但显式给 `tools` 白名单。
  *教训(2026-09-10):派通用型代理「只读复查、不改文件、不跑命令」,它照样改了几个文件、提交、
  赶在 PR 合并前进了 main。改得对不算数 —— 越权本身是问题。所以只读就在权限上只读,不靠嘱咐。*
- **外来 skill 用 `scripts/vendor-skills.mjs` 从上游同步进 `.claude/skills/`**,不在 settings 里声明插件
  (声明插件会带进几十个 MCP 工具的噪音;而且 claude.ai 里装的插件不进云会话 [实测✅ 2026-09-10])。

## 跨会话 = 仓库文件总线

会话之间没有共享记忆,一切经文件:

| 通道 | 载体 |
|---|---|
| 任务池 + 收件箱 | `docs/BACKLOG.md` |
| 行为流水(每会话一行) | `docs/journal.md` |
| 闸门误伤账 | `docs/gate-log.md` |
| 会话活表 | `docs/session-pool.md` |
| 设计定稿 | `docs/design/` |

**台账四件(前四行)直推 `main`,别的一切走自己分支。** 总线只有一条才叫总线 ——
各塔写在自己分支上的台账,别的塔读不到,看着通、实际各说各话(实测复发过两次)。

- 推台账:`node scripts/ledger-push.mjs "一句话说明"`。它先体检工作区,**有台账以外的改动就拒绝跑**
  (代码不许借这个口子上 main);先把 `origin/main` 并进来,再整份同步;撞车就报错让你手工解一次,不静默覆盖。
- **读台账读 `origin/main`**,不是自己分支。
- **main 上了分支保护之后**,直推会被拒。脚本自适应:
  - 打印 `✓ 台账已上 main` → 完事。
  - 打印 `⚠ 台账还没进 main` 并给出一个 `ledger/…` 分支 → **你要开 PR 并合**:
    `create_pull_request`(base=main,head=那个分支)→ `enable_pr_auto_merge`(CI 绿了自己合)。
    PR 报 not mergeable = 别的塔先合了它的台账,**重跑一次 `ledger-push`**,别去手改 PR 分支。
  - 怎么分辨「被规则挡了」和「别的塔抢先推了」:脚本不读 GitHub 的错误文字(措辞会变),
    而是 push 失败后现查 `origin/main` 的 sha 动没动 —— 动了 = 抢跑(自动重试),没动 = 规则挡的(转 PR 模式)。
  - 后半截靠记性 = 必漏,所以有**闸门12**:台账推成分支却没进 `origin/main`,收尾时拦一次。
- **harness 写完立刻合进 `main`,再说「各塔 merge 一下」** —— 顺序反了传的是空气。
- 要给别的目录开同样的直推口子,**先问用户** —— 默认口子只有台账四件。

**memory 只留跨项目的个人偏好和业务事实;跟本仓库有关的知识一律进仓库。**

## 塔

塔 = 一个板块一个常驻会话。**讨论住塔里(长命),任务是短命消耗品。**
一个板块一个塔,多个讨论在同一个塔里并行。协议见 `references/tower.md`。
**塔的形态由工作材料决定**:有材料、有持续讨论才开;没有就先不开。

默认八个板块(清单在 `.claude/belltower.json` 的 `boards` 里配,号段默认每板块一个百位段,也可配):

| 塔 | 板块 skill | 默认号段 | 开塔时机(建议) |
|---|---|---|---|
| plan | `tower-plan` | Q1xx | 一开始 |
| product | `tower-product` | Q2xx | 一开始 |
| dev | `tower-dev` | Q3xx | 设计评审过后 |
| data | `tower-data` | Q4xx | 随 dev |
| ops | `tower-ops` | Q5xx | 第一个对外里程碑前(之前 dev 兼) |
| biz | `tower-biz` | Q6xx | 一开始 |
| meta | `tower-meta` | Q7xx | 一开始 |
| test | `tower-test` | Q8xx | dev 开始交活时 |

## 派工人(塔不自己干活)

**配方见 `references/dispatch.md`** —— 立号 `Qn` → 写任务书(冷启动可接手)→ 活表加行推送 →
`create_session`(Claude Code Remote 的 MCP 工具)派出 → **同一轮排一个 10 分钟回查**(`send_later` 打回本塔)→
**塔自己查 PR 核实,不认工人的自述**。

- [实测✅ 2026-09-11]:云塔能派云工人,几分钟走完「读仓库 → 改文件 → 开 PR」。
- **同一次实测到工人会谎报**(回执写 merged,实际只是 open)—— 所以收活必须查外部事实(PR 状态、CI、`origin/main`)。
- 被问「现在谁在跑」:查 `list_sessions` + GitHub PR,**不要念活表**。活表是各塔自报的会过期;`IDLE` ≠ 干完(铁律7)。
- 立号前必须有用户那句「做这个」,**且查得到**(台账里的原话 + 时刻);别的塔的活不许替它立号(铁律6)。
  判据是「那句话存不存在、查不查得到」,不是「对谁说的」—— 用户在别的塔说过、原话已落台账的,算;
  塔自己想出来的,不算;别的塔转告但台账上找不到原话的,不算,先让它把原话落盘。

## 塔与塔之间:留言板 + 门铃

两条路,**缺一不可**:

- **文件总线**(拉模型):写台账,对方下次醒来读 `origin/main` 才看到。
- **门铃**(定向唤醒):`create_trigger` 带 `persistent_session_id` 绑对方会话 → `fire_trigger`,秒级送达
  [实测✅ 2026-09-10,两塔两分钟内醒来并合完 PR]。早先「定向唤醒会丢消息」的判断被这次实测推翻。
- `SendMessage` 够不到别的云塔(各在各的容器)[实测✅ 2026-09-10]。
- **门铃不替代留言板** —— 叫醒后该记的还得记台账。门铃里只说「去看台账哪一行」,别把正文塞进门铃。

对方会话 ID 怎么查、门铃怎么建、塔身份开局怎么现查,见 `references/tower.md`。

## 闸门维护(先硬后调)

实现 = `.claude/hooks/` 五个脚本 + `scripts/test-hooks.mjs`。闸门编号:bash 1–4 · edit 1–6 · mcp 10–11 · stop 6/7/8/9/12。
敏感路径的判据从 `.claude/belltower.json` 的 `sensitivePaths` 读。

- **加闸门**:必须能指到一次真实事故;必须带放行口子(或写明为什么不带);
  必须在 `test-hooks.mjs` 补**一红一绿**;改完做一次变异验证(故意弄坏判据,测试必须变红)。
- **删或降级**:唯一依据是 `docs/gate-log.md` —— 从没响过的删,误伤多的降成提醒。
  **凭感觉不许删。**
- **每次被拦**(不管冤不冤)记一行:日期 · 闸门 · 触发内容 · 冤枉吗 · 处置。
- **闸门自己坏了要放行**:所有 hook 解析失败一律 exit 0。软闸拦一次就放行。
  误放的代价是少一行 journal,误拦的代价是白烧一个会话的收尾加错误自诊扩散。

### 已知的反向激励

**想把危险的事写清楚,会被防危险的闸拦住。** 写测试夹具时里面的假 key 字面量会被
key 闸拦;写「别提交某某路径」的说明时会被提交闸拦。绕法不是关闸门,是让字面量不出现
(运行时拼接),或者把判据收窄到只看真正会执行的那一段。

### 还没堵上的口子

**铁律6 拦的是「立号」,拦不住「解除阻塞」。** 判据写在台账里,而台账是塔自己写的,塔可以给自己签字。
凡是会让别的塔开工的判定(「评审通过」「可以开发了」),落台账时附用户原话 + 时刻;

## 状态要派生,不要存储

写进仓库的每一个数(代码文件数、文档行数、「还在分支上」「零代码」),**要么现数,要么带上现数的命令**。
*教训:文档里手写的现状,在事实变了之后没人回来改,每个塔开局都读那句当真 —— 同一页纸上犯过两次。*
能由 hook 开局现数的(如 `session-start.mjs` 数代码目录,配置项 `codeDirs`),就别手写。
