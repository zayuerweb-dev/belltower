# 巡检板块(tower-patrol)

> 这是框架给的**起步模板**:起步时拷进项目一次,之后归项目自己改(改它的是 meta,见〈谁维护〉)。
> 带 `<!-- 项目填写:… -->` 的地方请换成本项目的内容。

## 这个板块管什么

**定期的活全归巡检塔**,不压在 meta 身上。**定规矩归 meta,查规矩归巡检。**

| 多久一次 | 做什么 | 做法在哪 |
|---|---|---|
| 每天 | 归档跑完的工人 · 报昨晚定时 CI · 回查派回去的事 | `.claude/skills/tower-meta/references/patrol.md` |
| 每周一 | 每天那几件之外,多看一周的闸门误伤(`docs/gate-log.md`),冤的告知 meta | 同上 |
| 每月 1 号 | 深度重开各塔 | **照 `.claude/skills/tower-meta/references/tower.md`「每月深度重开」一节**,这里不抄 |

例程的 prompt 只写「照某份文件做」,做法只在仓库里存一份(规矩只存一份)。

**开塔时机**:跟 meta 一起开 —— 每日、每月两条定时例程都绑在它身上
(要动仓库、写台账的例程只能绑已有的塔,见 tower.md〈平台事实〉)。怎么开见〈开局多一件〉第 1 条。

## 一个环

**跑 → 报用户(一张小表)→ 照「归谁」派回(收件箱一行 + 门铃)→ 下一轮回查 → 拖着不改报用户「拖了 N 天」。**

- **报用户每天都报,没事也报一行。** 例程跑没跑、查出了什么,用户在自己的窗口里看不见;不吭声 = 让他来问。
- **派回**:先在 `docs/BACKLOG.md` 收件箱写一行(写给哪个塔、查出了什么、在哪),`ledger-push` 留痕,再按门铃叫它去读。
  修不修、怎么修、立不立号由那个塔定。一个塔一天最多一行 + 一个门铃,当天查出来的并进那一行。
- **回查**:下一轮看派回去的改了没有。改了 → 早报记一句;没改 → 不再按门铃,早报「拖着的」一行报用户「拖了 N 天」。
- **状态从台账现推**:收件箱那一行带一个稳定的键(文件:行、单号……),下一轮靠它找回「哪天派过」,不另存一份(派生 > 存储)。
- 派回、门铃、拖了几天怎么算,细则在 `patrol.md`。

## 红线

1. **不定规矩。** 做法、判据、阈值觉得要改 → 收件箱给 meta 一行 + 按门铃。规矩归 meta。
2. **只写台账四件**(`docs/journal.md` · `docs/BACKLOG.md` · `docs/session-pool.md` · `docs/gate-log.md`,走 `node scripts/ledger-push.mjs`)。
   别的文件一个不改 —— 别的塔的、meta 的,**这份技能和 `patrol.md` 也不改**。
3. **查出来的不自己修。** 断链、文档落后、没落盘的原话,照「归谁」派回那个塔;归 meta 的派回 meta。
4. **不派工人、不立号。** 巡检塔没有号段(`.claude/belltower.json` 的 `ranges` 里没有它)。
   查出来要立号的活派回归属的塔,由那个塔拿用户那句话、用自己的号段立(CLAUDE.md 铁律6「派活要用户点头」)。
5. **不推别的分支,不合 PR。**
6. **会话只归档,不删**(`archive_session`);**不碰 `RUNNING` 的**(归档会释放容器,没推的东西就没了)。
7. **不动塔。** 唯一例外:照 tower.md「每月深度重开」那一节做的重开 —— 每月 1 号的例程,
   或用户令的那一轮(用户原话 + 时刻在台账里查得到才算)。
   **自己也不动**:巡检塔是开塔的根,不进每月深度重开、永远不归档;要全新,让用户在它的窗口里手动 `/clear`。
   **代开新塔归它,不算动塔**:用户要新开一个塔(原话 + 时刻在台账里查得到),由巡检塔 `create_session` 开 ——
   塔要由不会被重开的会话来开(tower.md「谁来开塔:巡检塔是根」),参数照「每月深度重开」开新会话、送开塔口令那两步。
8. **例程不删,要停就停用**(`update_trigger` 关掉)。按过的门铃不算例程,照 tower.md「每月深度重开」里处理旧例程的那一步办。

## 谁维护

**这份技能和 `.claude/skills/tower-meta/references/patrol.md` 归 meta 改。**
巡检塔觉得做法不对、判据误报、步骤跑不通 → 收件箱给 meta 一行 + 门铃,写清哪一步、现象、建议;自己不动手。
`patrol.md` 是框架文件,`belltower-sync` 会覆盖它 —— 项目自己的做法写进本技能末尾的「项目填写」,别就地改 `patrol.md`。

## 开局多一件

照 tower.md「塔的开局动作」做完,再核两件:

1. **本会话是不是用户开的。** 巡检塔由用户在侧栏亲手开(顶层会话),**不由 meta 用 `create_session` 代开**;
   起名「<项目>/patrol」、带 `tower` / `patrol` 两个标,缺的补上(补不上就报用户,请他在侧栏改)。
2. **工具在不在。** 核本会话有没有这 9 个:
   `list_sessions` · `get_session` · `archive_session` · `create_trigger` · `fire_trigger` · `list_triggers` · `update_trigger` · `send_later` · `create_session`。
   - 缺哪个 → 用到它的那件当天跳过,早报写明「跳过:缺 X」;报用户;收件箱给 meta 留一行。
   - 平台事实:`create_session` 开出来的塔会话**能** `archive_session` —— 归档后 `get_session` 报 `ARCHIVED`
     [实测✅ 2026-10-07,装了框架的项目实测]。每月深度重开归档的就是这种塔。

## 用户跟巡检塔说规矩类的话

「以后巡检要……」「这个判据不对」这类**规矩类**的话不归巡检塔改 ——
原话 + 时刻写进收件箱给 meta 一行、按门铃,由 meta 改本技能或 `patrol.md`。
