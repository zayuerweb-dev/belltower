# BACKLOG

四段式:**〇、执行队列**(能派的活)· **一、正在骗用户的**(红区)· **二、任务池** · **三、收件箱**。
SessionStart hook 会报红区条数(数的是「## 一、」段里 `### ` 标题的条数)。各板块干活时就地立条目,plan 定期消化。

## 〇、执行队列

> **这一段是「能派出去的活」,不是任务池。** 队列行**指向**二段的条目,不复制内容。
> 派发配方(任务书模板 / 怎么核 / 成本)见 `.claude/skills/tower-meta/references/dispatch.md`。

| 单号 | 板块 | 任务(指向二段条目) | 依赖 | 状态 | 谁派 |
|---|---|---|---|---|---|

<!-- 行的写法:| Q101 | plan | T3 · 一句话说清是什么 | — | 待派 | plan(用户 YYYY-MM-DD HH:MM 原话「……」) |
     「谁派」一栏必须带用户那句话的出处 —— 闸门4 看到新增的 `| Qnn |` 行会拦一次问「用户点过头吗」。 -->

**状态只有四个**:`待派` → `在跑` → `待收`(PR 开了,等塔核实)→ **收掉就删行**(痕迹留在 journal)。

> **删行 ≠ 活没了**:痕迹在 `journal.md`,PR 在 GitHub。用户要求清空队列时,
> 删的只是台账上的行 —— 在跑的工人不会因此停下,各塔照旧自己收自己的 PR。

### ★ 立号要用户点头 —— 禁止自主加 Q

**塔不许自己想出一个活、自己立号、自己派工人。** 立号前必须有用户那一句「做这个」
(可以是在别的塔说的,只要原话 + 时刻已落在台账上 —— 见 `CLAUDE.md` 铁律6、`dispatch.md` §11)。

| 谁决定 | 什么 |
|---|---|
| **用户** | **做哪件活**(哪件进队列、什么时候派) |
| **那件活所属板块的塔** | 立号 · 写任务书 · 派工人 · 收活核 PR —— **别的塔不许替它写** |

两条都别越:

- **越第一条 = 自主加 Q。** 用户没说要,塔自己挑了一件派出去、烧了钱。
- **越第二条 = 替别人立号。** 派发权是执行方的,替人写号就是替人做了决定。

> **教训**:一个塔自己挑了一件「该做的」活立号派出去,用户没说过要;又替另一个塔在队列里写了一行。
> 用户的反应是「这个号是谁创建的,我说过吗」「写号发号也不是你的活吧」。
> 「派发权收归执行方」原本就写在规矩里 —— **照抄了说法、没照抄做法**。

### 立号规矩(派生 > 存储)

**不记水位,而且按塔分段。** 号段制见 `dispatch.md` §3(默认每个板块一个百位号段:
plan `Q1xx` · product `Q2xx` · dev `Q3xx` · data `Q4xx` · ops `Q5xx` · biz `Q6xx` · meta `Q7xx` · test `Q8xx`,
板块清单可在 `.claude/belltower.json` 配置,号段跟着改)。**只在自己段内**取最大值 +1:

```
grep -ohE '(^|[^A-Za-z0-9])Q7[0-9]{2}' docs/BACKLOG.md docs/journal.md \
  | grep -oE 'Q[0-9]+' | sort -u | sort -t Q -k2 -n | tail -1      # 7 换成你的段
```

- **为什么分段**:「全局算最大值 +1」是「读一个数 → 干活 → 写回」,不是原子的。
  几个塔几分钟内各自算出同一个最大值、同时立了同一个号,**git 层面零冲突**(加的是不同的行),没人报错 [实测✅ 2026-09-11]。
  号段把「分配」变成了「派生」 —— 段由塔决定,塔本身唯一,跨塔不可能撞。
- **头边界不能省。** 裸写 `Q[0-9]+` 会匹配到**会话 id 里面**去 —— 实测从一个会话 ID 里挖出过一个不存在的条目号 [实测✅ 2026-09-11]。
- **号不复用**,哪怕那单已经删行。
- `Qn` 是**公共锚**:任务书名 = 分支名 = PR 标题 = 队列行 = journal 那一行,五处同一个号。

## 三、收件箱

> 跨板块流转的**权威**:一行一条,最新的在最上面。写完**再按门铃**叫对方来读(`create_trigger` + `fire_trigger`,
> 见 `tower.md`〈平台事实〉)—— 只写不按,对方不醒就永远看不到。
>
> 写法:`- YYYY-MM-DD HH:MM · <来源板块> → **<目标板块>** · <一句话说清是什么> · <文档路径 / PR>`
>
> 较长的交接可以用 `### 📮 给 <板块> 塔:<一句话>(<来源板块> YYYY-MM-DD HH:MM)` 小节。
> 对方处理完,把那一行删掉或划掉,痕迹进 journal。
