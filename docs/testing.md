# 测试:怎么证明闸门真在拦

一条命令跑全部:`node scripts/test.mjs`(CI 跑的就是它)。拆开看:

| 命令 | 测什么 |
|---|---|
| `cd framework && node scripts/test-hooks.mjs` | 每道闸门的红(该拦)/ 绿(不该拦)、配置读取、开局 hook、fail-open;末尾调 `test-ledger-push.mjs` |
| `cd framework && node scripts/test-ledger-push.mjs` | 台账推送的全路径:本地裸仓库 + `pre-receive` 钩子模拟分支保护、抢跑重试、转 PR 模式、闸门12 端到端 |
| `node scripts/test.mjs` | 上面两条 + init / sync 在临时项目里的真实行为 + scan-public 的每条规则 |

**所有用例都在临时沙箱里跑**,不读本仓库的台账和配置 —— 所以装进任何项目都能原样跑绿。
装进项目之后,项目里的 `node scripts/test-hooks.mjs` 就是同一套。

## 变异验证

**测试绿不等于闸门在拦。** 断言可能写反了、可能测的是别的路径、可能永远为真。
证明一条断言有用的唯一办法:**故意把实现改坏,看它红不红。**

### 做法

1. 把框架拷到临时目录(别在工作树上改)。
2. 挑一处实现,改成一个**看起来合理但错的**版本。例:
   - 身份锚:把活表行的正则从 `tower-(板块)` 放宽成 `[a-z]+-(板块)`;
   - 闸门9:把「从 settings 现读窗口」换成写死 `1_000_000`;
   - 代码目录:把 `config().codeDirs` 换成写死 `["src"]`。
3. **四查**,缺一条这次变异就不算数:
   - **只改了一处**(被替换的原文在文件里恰好出现一次);
   - **内容真变了**(改前改后字节不同);
   - **`node --check` 过**(不是语法错误让测试红的);
   - **目标输入真算错了**(用那条用例的输入单独跑一次被改坏的 hook,亲眼看到错的输出)。
4. 跑测试,**必须有对应的断言红**。零条红 = 这处实现没有测试在守,补断言。
5. 丢掉临时目录。

### 为什么要第 3 步的四查

- 没查「只改了一处」:替换没命中,文件原样,测试当然绿 —— 你以为「变异没被抓到」,其实是没变异。
- 没查 `node --check`:改出语法错误,整个 hook 崩掉、fail-open 放行,红的是别的断言,证明不了任何事。
- 没查「目标输入真算错了」:改坏的那处可能根本不在那条输入的路径上。

### 写断言时

- **期望值写死在测试里,别从实现里读** —— 从实现里读,实现错了期望跟着错,永远绿。
- 每个「从配置读」的功能至少要有一条**换了配置结果就变**的断言(只测默认值证明不了读了配置)。
- 红绿成对:「该拦的拦了」和「不该拦的没拦」各一条,只有一边的闸门迟早误伤或失效。
